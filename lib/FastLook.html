NAME

FastLook - binary search on contiguous monotonic ranges

VERSION

Version 0.00_00 (unimplemented)

SYNOPSIS

   use FastLook qw(
       bisectl bisectr bixectl bixectr
       blsrch0 brsrch0 blsrch1 brsrch1
       blsrch2 brsrch2 blsrchx brsrchx
   );

   # Input forms (left bisection)
   bisectl { ok($idx = $_) } [\&fun,]$hi; # $lo //= 0
   bisectl { ok($idx = $_) } [\&fun,]$lo, $hi;
   bisectl { ok($elt = $_) } \@list;      # $lo //= $[
   bisectl { ok($elt = $_) } \@list, $lo; # $hi //= 1 + $#$list
   bisectl { ok($elt = $_) } \@list, $lo, $hi;

   # Input forms (right bisection)
   bisectr { ok($idx = $_) } [\&fun,]$hi; # $lo //= -1
   bisectr { ok($idx = $_) } [\&fun,]$hi, $lo;
   bisectr { ok($elt = $_) } \@list;      # $hi //= $#$list
   bisectr { ok($elt = $_) } \@list, $hi; # $lo //= $[ - 1
   bisectr { ok($elt = $_) } \@list, $hi, $lo;

   # Output forms (as bi-/tri-section point)
   my $idx               = blsrch0 { ok } \@list;
   my ($idx, $cmp, $elt) = blsrch0 { ok } \@list;

   # Output forms (as dual trisection points)
   my $count       = blsrch2 { ok } \@list;
   my ($beg, $end) = blsrch2 { ok } \@list;

EXAMPLES

Who doesn't love examples!

You can compute the integer square root of $x by searching for the last integer $_ for which holds $_ * $_ < $x holds:

   sub isqrt {
       my ($x) = @_;
       bisectr { $_ * $_ <= $x } $x;
   }

   print isqrt(2025), "\n";  # 20+25 :O

The Guessing Game given in sort/search.go can be defined as follows:

   print STDERR "Pick an integer from 0 to 100.\n";
   my $answer = bisectl {
       print STDERR "Is your number <= $_? ";
       my $s = <STDIN>
       $s or return;
       chomp $s;
       $s eq 'y'
   } 0, 100;
   print STDERR "Your number is $answer.\n";

   __END__
   Pick an integer from 0 to 100.
   Is your number <= 50? y
   Is your number <= 25? n
   Is your number <= 38? n
   Is your number <= 44? n
   Is your number <= 47? y
   Is your number <= 46? y
   Is your number <= 45? y
   Your number is 45.

DESCRIPTION

Bisection algorithm

This section applies to the bisect* and bixect* subroutines:

   bisectl  bixectl
   bisectr  bixectr

There are two classes of binary search algorithm: the left bisection method and right bisection method. Naively, they deal with two classes of monotonic boolean-valued functions, otherwise known as predicates. Namely, call such a predicate ok. Then:

  • Left bisection assumes that the predicate is increasing. That is, if ok(x) is true, then ok(y) is true for all y >= x; and if ok(y) is false, then ok(x) is false for all x >= y. Visually, the image of the predicate looks like: 
       F F F ... F T T T   ok(x)
   1 2 3     6 7 8 9      x

    where there exists a unique point of true's first occurrence.

  • Right bisection assumes that the predicate is decreasing. That is, if ok(x) is false, then ok(y) is false for all y >= x; and if ok(y) is true, then ok(x) is true for all x >= y. Visually, the image of the predicate looks like: 
       T T T ... T F F F   ok(x)
   1 2 3     6 7 8 9      x

    where there exists a unique point of true's last occurrence.

Given the predicate ok and the bounds lo and hi, each algorithm attempts to find that unique point respectively.

To ensure the return value is mathematically consistent at all times, it is assumed that at least one point satisfies the predicate. This is the model employed by bisectl and bisectr. Namely,

  • Given [$lo, $hi] as its input, the left bisection method assumes that $ok->($hi) to true, and searches on the half-open interval [$lo, $hi) (that is, $ok->($hi) is never actually checked). When it cannot find any truth there, it returns $hi as a last resort. The order passed to the function is what you would expect: 
       bisectl { ok } $lo, $hi

    Commonly for arrays, you would set $hi to the length, which is one past the final index:

       bisectl { ok($list[$_]) } 0, @list

    This checks array elements at index 0 up to @list-1 only, and returns @list as a last resort. You may also omit 0 here as it is the default $lo for left-search functions.

  • Given [$lo, $hi] as its input, the right bisection method assumes that $ok->($lo) to true, and searches on the half-open interval ($lo, $hi]. When it cannot find any truth there, it returns $hi as a last resort. The order passed to the function is reversed: 
       bisectr { ok } $hi, $lo

    This time, you might set $lo to -1, which is one below the initial index:

       bisectr { ok($list[$_]) } $#list, -1

    This checks array elements at index $#list down to 0 only, and returns -1 as a last resort. You may also omit -1 here as it is the default $lo for right-search functions.

We will refer to the range of real, concrete index as the search range, which is [$lo, hi) for left search and ($lo, $hi] for right search. While the possible return values always lies on the closed interval [$lo, $hi], the search range is a half-open interval, whose exclusive endpoint depends on the search algorithm. As a basic sanity check you may check if the index lies in the search range to see if the search actually found anything, but see "Output forms" for more robust forms of error checking.

For each function above a variant is also provided by replacing the s with an x:

   bisectl -> bixectl
   bisectr -> bixectr

The constraint is relaxed in that the index returned need not be the first nor the last true index: any truth found on the half-open interval will be immediately returned. (Mnemonic: the x stands for eXists.)

Search algorithm

This section applies to the blsrch* and brsrch* subroutines:

   blsrch0  brsrch0
   blsrch1  brsrch1
   blsrch2  brsrch2
   blsrchx  brsrchx

More commonly, binary search is employed not on booleans, but on ordered collection of elements. The search is then done with respect to an ordering instead of a predicate.

The ordering is reflected by the trichotomous state of a numeric indicator, identified by being <0 (negative), =0 (zero), >0 (positive), similar to that returned by the <=> and cmp operators. A predicate is then composed on this ordering to yield the familiar boolean image from the previous section, where the same algorithm is employed. Let $_ denote this numerical ordering indicator. The predicate is chosen based on the suffix of the search function:

  • For the suffix 0, the predicate is $_ >= 0.
  • For the suffix 1, the predicate is $_ > 0.
  • For the suffix x, the search is performed as if the predicate is $_ >= 0, however it is short-circuited to return at the sight of any $_ == 0.

To see this more concretely, consider an increasing array of numbers:

   [1, 1, 2, 3, 3, 4, 5, 5, 5, 6, 8, 9, 9]   @list

We wish to know the first and last occurrence of the number 5. One first approach is to define the ordering $_ <=> 5, then apply the predicates $_ >= 0 and $_ > 0:

   [1, 1, 2, 3, 3, 4, 5, 5, 5, 6, 8, 9, 9]   @list
                     |
                     | $_ <=> 5            ordering
                     v
   -1 -1 -1  ...  -1  0  0  0  1  1  ...
                     |
                     | $_ >= 0             predicate 0
                     | $_ >  0             predicate 1
                     v
    F  F  F  ...   F (T) T  T  T  T  ...
    F  F  F  ...   F  F  F  F (T) T  ...
    --------------------------------------
    0  1  2        5 [6  7  8 ]9  10 ...     index

Run left bisection on the final two boolean images gives us the asymmetrical bounds 6 (inclusive) and 9 (exclusive). That is, we know 6,7,8 are all indices at which the array attains 5. The corresponding code that could produce these bounds is:

    my $lo = bisectl { $_ >= 5 } \@list;   # 6
    my $hi = bisectl { $_ >  5 } \@list;   # 9

Or, using the search algorithm:

    my $lo = blsrch0 { $_ <=> 5 } \@list;  # 6
    my $hi = blsrch1 { $_ <=> 5 } \@list;  # 9

which is equivalent to:

    my $lo = bisectl { ($_ <=> 5) >= 0 } \@list;
    my $hi = bisectl { ($_ <=> 5) >= 0 } \@list;

Another approach is to use the 5 <=> $_ ordering, apply the same predicates, but run right bisection instead:

   [1, 1, 2, 3, 3, 4, 5, 5, 5, 6, 8, 9, 9]   @list
                     |
                     | 5 <=> $_            ordering
                     v
    1  1  1  ...   1  0  0  0 -1 -1  ...
                     |
                     | $_ >= 0             predicate 0
                     | $_ >  0             predicate 1
                     v
    T  T  T  ...  (T) F  F  F  F  F  ...
    T  T  T  ...   T  T  T (T) F  F  ...
    --------------------------------------
    0  1  2        5[ 6  7  8] 9  10 ...     index

This gives us the asymmetrical bounds 5 (exclusive) and 8 (inclusive) for the indices at which the array attains 5. The code that could produce these bounds is:

    my $lo = bisectr { 5 >= $_ } \@list;   # 5
    my $hi = bisectr { 5 >  $_ } \@list;   # 8

Or, using the search algorithm:

    my $lo = brsrch0 { 5 <=> $_ } \@list;  # 5
    my $hi = brsrch1 { 5 <=> $_ } \@list;  # 8

which is equivalent to:

    my $lo = bisectr { ($_ <=> 5) >= 0 } \@list;
    my $hi = bisectr { ($_ <=> 5) >  0 } \@list;

Notably, to acquire bounds that are inclusive on both ends, you'd have to utilize search in both directions:

    my $lo = blsrch0 { $_ <=> 5 } \@list;  # 6
    my $hi = brsrch1 { 5 <=> $_ } \@list;  # 8

or offset the exclusive bound by 1 (only if you must avoid right search...)

    my $lo = blsrch0 { $_ <=> 5 } \@list;  # 6
    my $hi = blsrch1 { $_ <=> 5 } \@list;  # 9
    $hi--;     # now it is 8 and correct :)

Note that you would also have to reverse the ordering if the array was decreasing instead.

The ordering to use can be summarized as follows:

                     SORT ORDERING?
    ORIEN-  | f(i) <= f(i+1)  f(i) >= f(i+1)
    TATION? |  (increasing)    (decreasing)
   ---------+--------------------------------
     left   |  $want <=> $_    $_ <=> $want
     right  |  $_ <=> $want    $want <=> $_

Input forms

The first argument is always a callback, which can be passed using any syntax permitted by the & prototype. Notably, the callback may be given as a block, similar to sort BLOCK and grep BLOCK.

The callback receives its argument from $_, the default variable. Its exact argument is dependent on the input forms explained below: for index form, it is simply the index itself. For ARRAY and CODE form, it is the array element, or function image, at the given index. In either case, the function shall receive the index as the sole argument of @_. (This may be useful for identifying elements in an array of otherwise indistinguishable elements.)

Regarding the return value, the callback should behave like a predicate that meets the assumption described in "Bisection algorithm" for bisect* and bixect*, or an ordering that meets the assumption described in "Search algorithm" for blsrch* and brsrch*.

Input from here can be divided into three forms: index, ARRAY, and CODE. The $ prototype is used; that is, you can write 0, @list instead of 0, scalar(@list) in the case of searching on an array. Common across all forms, a pair of bounds ($lo, $hi) will be determined for the low-level bisection algorithms. The exact order is dependent on the search algorithm being employed: for left search, $lo precedes $hi. For right search, $hi precedes $lo.

In the index form, the function takes 2 to 3 arguments (including the callback). When passed 2 arguments, $hi is set to the second argument, and $lo is inferred depending on the search algorithm being employed. If it is a left search, $lo = 0, or else $lo = -1. This form is tried last if the second argument is neither an ARRAY ref nor a CODE ref, but in principle you should be only passing a scalar (number) for both the second and the third argument.

In the ARRAY form, the function takes 2 to 4 arguments (including the callback). When passed 2 to 3 arguments, both or one of $lo and $hi are inferred, depending on the search algorithm being employed.

  • If passed 2 arguments, then both bounds are implicit. For left search, $lo is set to the initial index of an array ($[), and $hi to one past the final index ($#list + 1). For right search, $hi is set to the final index ($#list), and $lo is set to one below the initial index (-1).
  • If passed 3 arguments, then the "end" bound is implicit. For left search, $lo is set to the second argument, and $hi is set according to the rules above. For right search, $hi is set to the second argument, and $lo is set according to the rules above.

Note that under Perl's default 0-based array indexing, $[ == 0, $#list + 1 == @$list, and $[ - 1 = -1.

In the CODE form, the function takes 3 to 4 arguments (including the callback), and arguments 3--4 are processed in the same way arguments 2--3 are processed in the index form. Note that the CODE should return a reference to the image element for glob aliasing to work. If the element itself is an ARRAY/HASH ref, it should be a ref to that ARRAY/HASH ref.

Output forms

In scalar context all functions (excluding blsrch2 and brsrch2) return the index they found, possibly a last-resort index lying beyond the search range. This is, admittedly, not the most helpful for searching when the match ought to be exact, not just satisfying a monotonic predicate. In list context, therefore, these functions return parameters that may be of more help. One may use the mnemonic ICE for the order of these parameters: index, comparison indicator, and element.

The comparison indicator is the return value of the predicate or ordering function at this index, depending on whether this is a bisection or a binary search algorithm. If this index is a last-resort index lying beyond the search range, this value is undef. The element is the value passed to the previously described predicate or ordering function at the same index, or undef too if the index is a last-resort index.

To find the first element equal to a target value, not just equal to or greater than it, you can therefore do this:

    sub search {
        my ($array, $want) = @_;
        my ($idx, $cmp, $elt) = blsrch0 { $_ <=> $want } $array;
        if (!defined $cmp) { print "$want not found anywhere\n"; }
        elsif ($cmp == 0)  { print "$want not found; the best "
                                 . "I got was $elt at [$idx]\n"; }
        else               { print "$want found at $idx :)"; }
    }

    my $list = [1, 1, 2, 3, 3, 4, 5, 5, 5, 6, 8, 9, 9];
    search $list => 5;
    search $list => 7;
    search $list => 10;

This should print:

    5 found at [6] :)
    7 not found; the best I got was 8 at [10]
    10 not found anywhere

If you are fine with finding any element equal to it, you can substitute blsrch0 with blsrchx or brsrchx. Note that the same checks are still necessary to ensure that the result is meaningful.

Subroutines

The following is a summary of all the subroutines provided by this package. All subroutines are exported on demand only.

bisectl
bixectl

Perform left bisection with respect to a predicate on the half-open interval [$lo, $hi), where $lo precedes $hi in the argument array. The prototype is &$;$$.

The predicate should be increasing over every pair of adjacent indices it is defined on. That is, true values always follow false values:

   F F F ... F T T T   ok(x)
   1 2 3     6 7 8 9      x

Set $ok->($hi) = 1. The return value of bisectl is the unique index $x on the closed interval [$lo, $hi] such that:

  • $ok->($x) is true.
  • For all valid index $y < $x, it follows that $ok->($y) is false.

The return value of bixectl is any index satisfying the first constraint. It is guaranteed to be consistent across invocations due to the nature of binary search.

If the interval [$lo, $hi] is empty, return $hi.

bisectr
bixectr

Perform right bisection with respect to a predicate on the half-open interval ($lo, $hi], where $hi precedes $lo in the argument array. The prototype is &$;$$.

The predicate should be decreasing over every pair of adjacent indices it is defined on. That is, true values always precede false values:

   T T T ... T F F F   ok(x)
   1 2 3     6 7 8 9      x

Set $ok->($lo) = 1. The return value of bisectr is the unique index $x on the closed interval [$lo, $hi] such that:

  • $ok->($x) is true.
  • For all valid index $y > $x, it follows that $ok->($y) is false.

The return value of bixectr is any index satisfying the first constraint. It is guaranteed to be consistent across invocations due to the nature of binary search.

If the interval [$lo, $hi] is empty, return $lo.

In general, a return value of $hi (for left search) and $lo (for right search) is not meaningful as it is the only index taken to be true for granted. Caller should handle it separately, or check if the comparison indicator and/or element are defined by calling in list context.
